要求：
1. **模板优先**：以模板的母版、版式、页数、字体、配色为准；不要另起一套视觉。模板页数不足时，按文末「模板适配规则」合并内容，不要机械套用默认页码。
2. **内容必须覆盖四大板块**：**作品背景、技术实现方式、作品使用场景、未来完善方向**；每个板块至少 1 页。三大亮点（多链路、自学习、人工辅助）作为「技术实现方式」的重点展开，每个亮点至少 1 页深挖。
3. 受众：业务负责人、客服/风控负责人、技术评审；先讲价值，再讲实现与边界，不堆术语。
4. 每页输出：**所属板块 / 模板页或版式 / 页面标题 / 核心信息（一句话）/ 3–5 条要点 / 可视化或配图占位 / 演讲备注**。可在四大板块之外增加“项目现状（可选）”“Q&A”。
5. 视觉：若模板有既定配色，**以模板为准**；无模板时默认白底 + 少量紫色（#6D28D9），干净、可信、企业级；不要赛博朋克、不要深色黑客风。
6. 只用语料中的事实与数字；没有数字的地方写“示例/目标”，不要编造。
7. “自学习”必须写成 **检索式案例记忆 + L2 反馈加权**，不是模型微调，也不自动改规则/阈值。
8. 不暴露 API Key、内部地址、客户隐私；不写“100% 识别”“完全替代人工”。
9. 若模板缺少合适的版式（如证据链、权重曲线、系统边界），给出“替代版式建议”，不要硬塞。

11. 输出格式：每页用 `---` 分隔；最后附一页“Q&A 预判问题与回答”。

## 一、项目一句话

**迹觅·Evidence**：让每一张索赔图、每一份诊断单、每一条种草帖，都有一条可解释、可追溯、可复用的证据链。

面向美妆/电商客服场景，识别两类欺骗行为：

- **退款欺诈**：AI 生成的商品破损图索赔；诊断单真伪及其与客户陈述的矛盾；
- **种草内容真伪**：图片 + 文案 + 评论区综合判断真实分享还是未披露的商单营销。

当前系统已完成真实 API 端到端验证：从触发判断、多源取证、裁决，到人工复核、案例沉淀、后续检索与反馈加权，形成闭环。

---

## 二、业务痛点

1. **造假成本急剧下降**：生成式模型让破损图、诊断单、素人种草图几分钟即可批量生产。
2. **单模型不可靠**：视觉模型只能看可见痕迹，对不可见水印、模型指纹、跨案复用图无能为力。
3. **人工复核是黑箱**：经验留在个人脑子里，同类案件反复从零判断，复核质量不稳定。
4. **成本与合规压力**：每次分析可能调用多个模型和外部服务，缺少预算闸门与审计。
5. **证据链缺失**：只给“高风险”结论，业务不敢拒赔；需要能解释“为什么”、能回溯“看了什么、调了什么工具”。

## 三、方案总览

**多阶段 Agent 流水线 + 多源证据融合 + 人工在环的案例记忆 + 反馈加权。**

```
触发判断（零 LLM）
  → 本地取证（EXIF / 图片指纹）
  → AI 生成预检（Sightengine，全部图片）
  → 知识库召回（方法/案例/标准）
  → 先前案例召回（人工判决沉淀）
  → 视觉定位（Qwen：AI 篡改位置 + 与客户诉求的关系）
  → 调查 Agent（知识库 / 联网 / 识图 / 会话记录）
  → 一致性核对
  → 裁决（必须引用证据编号）
  → 报告 / 成本汇总
  ↘ 人工复核 → 案例文档 → 先例索引 → 反馈加权（回流到检索与证据权重）
```

关键设计：
- 规则/语义先判断“要不要分析”，**触发阶段零 token**；
- 每个节点可观测：输入、输出、思考摘要、工具调用、RAG 命中、证据；模型返回按字段渲染，不直接铺原始 JSON；
- 结论必须落到 evidence_id，报告与事件流一致；
- 人工复核不是事后补丁，而是下一轮系统记忆的入口。

## 四、三大亮点

### 亮点 1：多链路（多源证据链路 + 多阶段 Agent）

**一句话：不是“一个模型看图”，而是“多条独立证据互相印证”。**

- 规则/语义触发：关键词 + 5 条消息窗口 + 余弦相似度，先判断诉求与场景；
- 语义命中分三档：**完全命中 / 疑似 / 普通**（只表示匹配强度，**不是案件风险**；案件风险仍为高/中/低）；
- 本地取证：EXIF、图片指纹（pHash 复用检测可配置开关）；
- doctrine 知识库：鉴别方法、欺诈模式、判定原则，混合检索（向量 + BM25 + RRF）；
- 先前案例：人工判决沉淀的独立索引，作为先例证据；
- 第三方预检：所有图片先送 Sightengine，检测不可见水印/模型指纹；分数只是“可能经过 AI 生成/编辑”的高价值线索，不指明位置，**不能单独定罪**；
- 视觉定位：Qwen 收到检测分后，定位 AI 篡改的具体区域，并判断与客户诉求的关系（related / unrelated / uncertain）；
- 裁决：只有“篡改落在支撑索赔的关键区域/字段”才支持欺诈；篡改只在人脸/背景等无关区域时，按诉求对象本身的真实性判断，不升级风险；
- 调查 Agent：按需调用知识库、联网搜索、识图、历史会话等工具；
- 裁决输出：综合证据方向与权重，给出结论、置信度、反方要点、建议动作。

**业务价值**：降低单模型误判；每一条结论都能回答“依据是什么”。

### 亮点 2：自学习（L1 案例记忆 + L2 反馈加权）

**一句话：人判过的案子，会变成系统下一次判断的先例，并越用越可靠。**

L1 案例记忆：
1. 系统建议复核的运行，进入「人工判决」；
2. 人工选择 **欺诈 / 真实 / 证据不足**，写明理由；
3. Agent 仅在缺少关键事实时追问（可以一轮都不问），理解“为什么这么判”；
4. Agent 生成结构化案例：案件定义、案件细节、判决原因、关键证据、适用边界；
5. 案例进入**独立的先前案例索引**（与 doctrine 知识库隔离）；
6. 后续分析新增“先前案例召回”节点，先例作为证据参与推理。

L2 反馈加权（当前已完成）：
- 只处理**被本案裁决明确引用**的先例；
- 复核完成后，Agent 根据人工判决**意图**推断：
  - `adopted` 采纳：依赖/肯定先例结论或推理；
  - `overturned` 推翻：明确认为先例判错/误导；
  - `not_applicable` 不适用：先例本身可能正确，但与本案差异大，**不降权**；
  - `neutral` 中性：无法判断或影响很小；
- 只有采纳/推翻更新 Beta 后验：初始 α=2、β=2，采纳 +1α、推翻 +1β，可靠性 = α/(α+β)；
- 置信度 <0.6 记中性；
- 可靠性参与**检索排序**与**证据权重**：
  - 排序：`rrf × (0.7 + 0.6 × reliability)`；
  - 证据权重：欺诈/真实 `0.3 + 0.6 × reliability`，证据不足 `0.2 + 0.4 × reliability`；
- 前端可在「先前案例」查看可靠性、采纳/推翻次数与**权重发展时间线**；复核面板展示本次“先例反馈”。

边界（必须讲清）：
- 这是**检索增强 + 反馈加权**，不是模型微调；
- **不自动修改规则/阈值**；判决权仍在人；
- 先例可靠性只反映“先例是否可信”，不反映“是否适用于本案”；
- 案例可审计、可回滚；先例必须比较相似点/差异，不能无条件照搬。

**业务价值**：经验从“个人记忆”变成“组织资产”；同类案件越用越准，而不是越用越依赖某个人。

### 亮点 3：人工辅助（Human-in-the-loop 人机协同）

**一句话：人不是最后一道补丁，而是系统记忆的来源。**

- 只对“系统建议复核”的运行开放人工判决，避免所有案件涌入；
- 复核员看到完整**对话记录**、事件流、报告、工具调用、证据链；
- 对话记录常驻运行详情页签之上，切换页签不丢失；长对话卡片内部滚动，不撑高页面；
- Agent 通过**SSE 流式追问**理解判决依据；追问与案例文档都逐 token 输出；
- 追问不是必选项：理解判决依据即可直接生成，最多 4 轮；
- 三种判决都是终局结论；“证据不足”也按明确判断沉淀，不写成“挂起待补充”；
- 复核完成后，Agent 自动推断被引用先例的采纳/推翻，并回写权重历史。

**业务价值**：把“人审”从成本中心变成数据飞轮；人越用越省力，系统越用越懂业务。

## 六、技术事实库（写作时只引用这里）

### 系统组成
- 后端：Python 3.13 + FastAPI；Agent 编排：LangGraph；SQLite（运行/事件/报告/复核/案例/反馈）；Chroma + BGE-small-zh + BM25（RRF 融合）。
- 模型：DeepSeek Flash（主推理，OpenAI 兼容）；Qwen3.7-Flash（识图定位，阿里云 DashScope 兼容模式，识图预算 8192 tokens）；Sightengine（AI 生成预检，`models=genai`，所有图片先检测）；Tavily（联网）。
- 前端：Vue 3 + Vite + TS + Tailwind；管理观测台深色；演示客服平台白 + 少量紫。
- 对外接口：`/api/v1/analyze/check`、`/runs`、`/runs/{id}/confirm`、状态/报告/事件/SSE 等；演示平台只通过这些接口接入。

### 触发与去重
- 规则/关键词 + 语义余弦相似度；分析窗口最近 5 条消息；图片可在窗口内回看；
- 语义命中等级按“分组阈值 + 相对余量”分为 **完全命中 / 疑似 / 普通**，与案件风险（高/中/低）是两个维度；
- 证据指纹去重 + 活跃运行守卫 + 冷却期；触发判断零 LLM 成本。

### 图片与第三方检测
- EXIF / 图片指纹；复用图检测可配置开关；
- 所有图片先送 Sightengine 做 AI 生成预检，结果按图缓存；
- 检测分只作为“可能存在 AI 生成/编辑”的高价值线索，不指明位置，不能单独定案；
- Qwen 收到分数后定位篡改区域，输出 `tamper_relation_to_claim`：
  - related：篡改落在产品破损处/单据关键字段/帖子关键场景，支持欺诈；
  - unrelated：篡改只在人脸/背景等无关区域，诉求对象未见异常；0.90–0.95 且诉求区域真实时可按真实性判断，≥0.95 时不得判真实，至少 suspicious；
  - uncertain：无法定位或无法判断关系；0.90–0.95 可结合定位判断，≥0.95 时至少 suspicious，并说明“极高分数说明图片为 AI 生成，但识图无法定位具体位置”；
- **阈值分层**：<0.90 不纳入 AI 生成考量，仅记录；0.90–0.95 纳入考量但不触发硬约束；≥0.95 触发硬约束——任一图片达到该分数，最终不得 `likely_genuine` 或 `inconclusive`，至少 `suspicious`，并在摘要说明原因；
- 医疗单据同样先预检；只有诊断、日期、患者、印章等关键字段被编辑才计入索赔风险。

### 人工复核
- 复核资格：结论为 `suspicious/fake_claim`，或建议 `manual_review`；
- 判决：欺诈 / 真实 / 证据不足（均为终局结论）；
- Agent 最多 4 轮追问，可以零追问；支持随时强制生成；
- 追问与案例文档通过 **POST SSE** 流式输出；
- 先前案例支持删除：删除已沉淀案例时同步清理 Chroma/BM25 索引，来源复核回到可重新生成状态，复核记录保留；
- 运行详情对话记录常驻页签之上，内部会话/外部 inline/历史回填三种来源，长对话内部滚动。

### 可观测与渲染
- `llm_result` 事件携带 `purpose` 与 `content_preview`（≤3000 字符）；
- 前端按 JSON 形状渲染：裁决（结论/风险/置信度/证据引用/反方要点/建议动作）、调查（新增证据/待确认）、一致性（矛盾/不一致/评分）、识图（分区/字段/篡改位置/诉求相关性/不确定因素）；
- “开始分析”的规则决策与工具调用参数均字段化展示；思考流只保留结构化摘要，不再铺原始 JSON。

### 先例反馈（L2）
- 仅处理被本案裁决 `evidence_refs` 引用的先例；
- Agent 按人工判决与追问回答推断 `adopted/overturned/not_applicable/neutral`；
- Beta(2,2)：采纳 +1α、推翻 +1β；可靠性 `α/(α+β)`；置信度 <0.6 记中性；
- `not_applicable` 不降权；`neutral` 不改权重；
- 可靠性参与检索排序与证据权重；前端展示权重发展时间线；
- 示例验证：某先例被采纳后 0.50 → 0.60，排序分 0.0293 → 0.0311，证据权重 0.66。

### 成本
- DeepSeek Flash 谷值（CNY/百万 tokens）：缓存命中输入 0.02、未命中 1、输出 4；系统按每 1K 的 0.00002 / 0.001 / 0.004 计算；峰时价格翻倍，但当前**仅按谷值估算**；
- 缓存命中 token 会从 usage 中拆分，按命中价计费；
- 触发零 token；识图/第三方按图缓存；工具调用有预算闸门；
- 示例：一次完整分析约 ¥0.01–0.04；一次复核约 ¥0.014（以实际 usage 为准）。

### 验证
- 后端 **127 个测试通过**；前端 `vue-tsc` 通过；
- 真实 API 端到端：Sightengine 0.99 → Qwen 未定位到可见篡改（uncertain）→ 裁决 suspicious/medium，未仅凭分数判欺诈，也未判真实；
- 单元测试覆盖：<0.90 中性记录；0.90–0.95 纳入考量但不强制；≥0.95 触发“不得判真实，至少 suspicious”；related → 支持 fake_claim；unrelated 且诉求区域真实 + <0.95 → 支持 likely_genuine；
- 人工判决 → 流式追问（0–4 轮）→ 案例生成 → 后续分析召回先例 → 反馈加权，全链路已验证；
- 流式验证：单次复核产生 2400+ token 事件，案例文档逐 token 输出；
- 观测台实测：运行复核徽标、对话记录、先例可靠性、权重发展时间线均可用。

## 九、Q&A 预判（GPT 可生成一页）

1. **和直接用大模型看图有什么区别？**
   单模型只看可见内容；我们有多源证据、第三方不可见水印检测、知识库、联网与人工先例，且每条结论可追溯。

2. **“被采纳”是不是只要 LLM 引用了先例？**
   不是。只有被裁决引用、且复核 Agent 结合人工理由判断“人工确实依赖/肯定该先例”才算采纳；先例正确但与本案不适用，不算推翻、也不降权。

3. **自学习会不会把错误判决学进去？**
   只对有引用、有人工复核意图的先例更新；Beta 后验平滑；置信度不足记中性；案例可审计、可回滚；规则不会被自动修改。

4. **人工复核会不会成为瓶颈？**
   只对系统建议复核的运行开放；Agent 可以零追问直接成稿；流式交互降低等待感。

5. **成本会不会失控？**
   触发零 LLM；识图/第三方按图缓存；预算闸门；按谷值计费，单次分析为分级成本。

6. **如何接入现有客服平台？**
   通过 `/api/v1/analyze/*` 接口；演示平台就是独立接入的参考实现。
